# OpenAPI Documents (`HeraOpenApi`, `@sibylline-labs/hera/openapi`)

`HeraOpenApi` (`src/core/openapi/`) builds an OpenAPI 3.1.0 document from a table of operations whose request and response shapes are Effect schemas. A service's published spec and its decoders therefore come from the same schemas. It is pure and runtime-agnostic, so a build script, a CLI or a Worker can all call it.

| Member | What it is |
|---|---|
| `HeraOpenApi.document(spec)` | A `HeraOpenApiSpec` (info, servers, security schemes, operations) → a `HeraOpenApiDocument` |
| `HeraOpenApiOperation` | One operation: method, path, `params` / `query` / `body` schemas, responses |

---

## 1. Describing an operation

| Field | Becomes |
|---|---|
| `method`, `path` | `paths[path][method]`; `path` is in OpenAPI form (`/things/{thing_id}`) |
| `params` (a `Schema.Struct`) | one `in: path` parameter per field, always required; the fields must match the path's `{name}` placeholders |
| `query` (a `Schema.Struct`) | one `in: query` parameter per field, required unless the field is `Schema.optional` |
| `body` | a required `application/json` request body |
| `responses` | keyed by status (`"200"`) or `"default"`; `contentType` defaults to `application/json` |

Each schema is generated by Effect (`Schema.toJsonSchemaDocument`, the encoded side of `Schema.toCodecJson`), and its refs are rewritten to `#/components/schemas/<name>`. Every named definition joins one `components.schemas` pool. Two identical definitions under one identifier dedupe; two different ones throw a `TypeError` naming the identifier, so one operation never silently documents another's shape.

## 2. Using it

```ts
import { writeFileSync } from "node:fs"
import * as Schema from "effect/Schema"
import { HeraOpenApi, type HeraOpenApiOperation } from "@sibylline-labs/hera/openapi"

const Widget = Schema.Struct({ id: Schema.String, name: Schema.String }).annotate({ identifier: "Widget" })

const operations: ReadonlyArray<HeraOpenApiOperation> = [
  {
    operationId: "widgetsGet",
    method: "GET",
    path: "/v1/widgets/{widget_id}",
    security: [{ bearer: [] }],
    params: Schema.Struct({ widget_id: Schema.String }),
    responses: { "200": { description: "ok", schema: Widget } },
  },
]

const spec = HeraOpenApi.document({
  info: { title: "Widgets", version: "1.0.0" },
  servers: [{ url: "https://api.example.com" }],
  securitySchemes: { bearer: { type: "http", scheme: "bearer" } },
  operations,
})

writeFileSync("openapi.json", `${JSON.stringify(spec, null, 2)}\n`)
```

## 3. Determinism

`paths`, the methods under each path and `components.schemas` are sorted, so the same input yields a byte-identical `JSON.stringify`. A regenerated spec diffs only when the contract changes, so a service can commit its document as a golden fixture and compare it in a test.

## 4. Routing the same paths

`Hera.router` treats a `{name}` segment exactly like `:name`, so a route can carry the OpenAPI-form path straight from its operation table (`/v1/widgets/{widget_id}`) and its handler reads `params.widget_id`.
